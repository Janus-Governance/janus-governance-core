# Core Lite v0.2 conformance inventory and schema/stateful foundation

This directory is the Gate 2 inventory and intentionally incomplete conformance-test-vector foundation for Janus Core Lite v0.2 at commit `8aae702a1bb11032f86a8a32e164e3a68fc961da` (SHA-256 `709279f32abe18d792c68299b080c349e1ed0c45780775581aacf32484e78b0b`).

The catalog contains 22 lexical MUST/MUST NOT parents, 43 lexical atomic requirements, 113 declarative constraints, and 156 total entries. D106 is a late inventory recovery and stateful implementation of the existing Core rule that a canonical `AUDIT_LOG` record uses `payload.event_id` as its identity. D107–D109 recover existing E+, E−, and optional human-judgment clauses without changing Core Lite v0.2 semantics; D107 and D108 remain `NOT_IMPLEMENTED`, while D109 is non-gating. The schema foundation adds six JSON Schema 2020-12 profiles and 42 manifest-driven fixture cases.

Every schema is a versioned Janus JSON conformance test-vector profile subordinate to Core. It is not a universal Core serialization, new canonical semantics, a replacement for Core, a runtime contract, a Framework identity or competence resolver, or proof of conformance. Objects remain open. References, identities and times have no invented UUID, URI, date-time or ordering syntax.

Exactly 19 atomic obligations receive `STRUCTURAL_SCHEMA_COVERED` and `REQUIREMENT_COMPLETE` based on resolvable schemas, fixtures and deterministic tests. D066–D075 receive only `PROJECTION_COVERED`; their unresolved findings remain. Human, Framework and stateful obligations outside the explicit structural allowlist remain incomplete.

The corrected deterministic in-memory stateful history/reference test profile completes 31 requirements and projects 7 more across 57 scenarios. D025, L019-A01, D076, D077, and D079 remain stateful technical projections: their scenarios are preparatory evidence only, because `observation.outcome`, `observation.reproducible`, `expectation.due_status_determinable`, and `schema_context.covers_considered_records` are test-only non-constitutive oracles rather than results derived by searching frozen sources, deriving due status, reproducing an observation, enumerating considered records, or calculating schema coverage. Its dependency-free boundary guard checks the test wrapper, required `AUDIT_LOG` event type and event ID, identity equality, `HUMAN_DECISION` shape and placement, Audit Writer dispatch, applicable references, and uniqueness in that order. The recursively frozen state, logs, preconditions, Audit Writer registry, aliases, alias targets, expectation versions, deterministic scopes, schema contexts, observation artifacts, evidence records, and procedure identity/version are test-profile preconditions only. Aliases are a noncanonical test adapter; `CHECK_OBJECT_REFS` and logical ordinals are explicit technical adapters. Automatic `object_refs` governance applies only where Core defines it here, notably `HUMAN_DECISION`, while typed `antecedent_ref` resolution remains for correction, supersession, and void records.

D024 is evidenced by an authorized Audit Writer incorporating a governance event into `AUDIT_LOG`, followed by an atomically rejected replacement that preserves the event byte-equivalently. The Phase A scenario set retains the same 41 scenario identities.

Recorded P2 follow-ups remain outside this transaction: subject-correct positive evidence for D023, the inferred Framework note in L022-A01, and verification classification of D100/D101.

The E−/omission foundation appends `OMISSION_DETECTED` only for a fully qualified, reproducible absence within the recorded scope and cutoff, and only to `AUDIT_LOG` through the authorized Audit Writer. A presence result is the technical outcome `EXPECTATION_SATISFIED`; it is neither E− nor `HUMAN_DECISION`. D080 deliberately remains incomplete because this bounded foundation does not independently evidence every §5 condition.

This stateful foundation is not a runtime, authority store, full structural validator, JSON Schema substitute, canonical serialization, external clock, or exhaustive E− implementation. It does not model origin, humanity, authority, will, or competence, and it does not claim conformance.

The dependency-free baseline remains `EXPECTED_INCOMPLETE` with exit 1 and `conformance_claimed: false`. Schema validation is defined for exactly `ajv@8.20.0` through `ajv/dist/2020.js`, but the AJV suite is not executed in this transaction because installation and network access are prohibited.
